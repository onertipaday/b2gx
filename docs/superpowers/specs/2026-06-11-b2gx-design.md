# b2gx — a modern CLI/library reframe of Blast2GO

**Date:** 2026-06-11
**Status:** Design approved, ready for implementation planning

## 1. Purpose & scope

`b2gx` is a Python (`uv`) library + CLI that re-implements the core Blast2GO
functional-annotation methodology as a scriptable, container-native tool for
HPC/SLURM bulk pipelines. No GUI. It transfers GO/EC/KEGG annotations to a set of
query proteins by homology to NCBI nr, applying Blast2GO's Annotation Rule, and
emits tables that feed directly into a downstream bulk-RNA-seq differential
expression / enrichment workflow (clusterProfiler GO+KEGG).

### In scope (all four Blast2GO stages)
- **Mapping** — DIAMOND hits → candidate GO terms via an accession→GO reference.
- **Annotation Rule** — Blast2GO's signature scoring + GO-DAG abstraction + filtering.
- **InterPro merge** — merge GO terms from an InterProScan run.
- **EC + KEGG mapping** — enzyme codes and KEGG KO/pathway assignment.

### Explicitly out of scope
- BLAST/DIAMOND execution itself (run separately on HPC; tool consumes its output).
- InterProScan execution (consumed if provided).
- GO enrichment / statistics and visualization — handled downstream by the user's
  R bulk-RNA-seq DEA pipeline (clusterProfiler). `b2gx` produces the input tables.
- Any GUI.

## 2. Key decisions (resolved during brainstorming)

| Decision | Choice |
|---|---|
| Form factor | Python (`uv`) library + Typer CLI, packaged as an apptainer image |
| Alignment input | DIAMOND tabular (outfmt 6) **with `ppos`** column required |
| Query organism | RefSeq prokaryote proteins; `sseqid` = RefSeq protein (WP_/NP_/XP_) |
| accession→GO source | UniProt `idmapping_selected.tab.gz`, indexed on the **RefSeq** column |
| EC / KEGG source | UniProt idmapping (EC + KEGG/KO columns) — avoids KEGG REST license |
| Reference data | Hybrid: managed `fetch`/`update` downloader + versioned local cache; runs pin a cached version. HPC nodes have internet. |
| Outputs | clusterProfiler tables + Blast2GO `.annot` + rich per-sequence table + summary/GO-slim + coverage report |
| Execution | One-shot `run` and per-stage subcommands; per-stage Parquet checkpoints for SLURM resume |
| Acceptance gate | End-to-end on `GCF_023558375.1` + concordance benchmark vs eggNOG-mapper |


**Execution model.** `b2gx run` executes the full pipeline; each stage is also a
subcommand (`map`, `annotate`, `interpro`, `eckegg`, `write`) reading/writing a
Parquet intermediate so a SLURM job can checkpoint/resume. Reference cache and
intermediates default under `/mnt/nfs3/sonegop`, overridable by flag/env.

**Container.** `apptainer/b2gx.def` builds from a slim Python base, `uv sync
--frozen` into the image; reference data is **not** baked in (kept in the
bind-mounted cache so the small image is decoupled from DB updates). Image stored
in `/mnt/nfs3/sonegop/images/apptainer`, reused. CPU-only (no `--nv`).

```
apptainer exec -B /mnt/nfs3/sonegop b2gx.sif b2gx run --config run.yaml
```

## 4. Data model

One record per query sequence, carried through every stage; hot paths operate on
Polars DataFrames keyed by `seq_id`, with these dataclasses as the logical
contract and the shape of the rich output. Transforms are immutable (each stage
returns new records).

```python
@dataclass
class Hit:
    sseqid: str            # nr subject accession (WP_/NP_/XP_)
    ppos: float            # % positives of best HSP  -> similarity
    evalue: float
    bitscore: float
    hsp_cov: float

@dataclass
class CandidateGO:
    go_id: str
    evidence: str          # source evidence code from the contributing hit
    sseqid: str            # hit accession that contributed this candidate
    similarity: float      # ppos of that hit

@dataclass
class GOAssignment:
    go_id: str
    source: Literal["blast", "interpro"]
    evidence: str          # source evidence code
    score: float | None    # Annotation Rule score (blast-derived only)

@dataclass
class SequenceAnnotation:
    seq_id: str
    hits: list[Hit]
    candidate_gos: list[CandidateGO]   # pre-scoring (mapping stage)
    assigned_gos: list[GOAssignment]
    interpro: list[str]
    ec: list[str]
    kegg_ko: list[str]
    kegg_pathways: list[str]
    top_hit_desc: str | None
```

## 5. Reference data layer

Versioned cache with a `manifest.json` (source URL, download date, file hash,
version) so every run pins exact reference versions for reproducibility. Runs
verify each referenced file against the manifest hash before starting and fail
fast on missing/mismatched data.

| Reference | Source | Used by | Notes |
|---|---|---|---|
| `go-basic.obo` | GO release | DAG, propagation, levels, GO-slim | `obonet` → `networkx` DiGraph |
| accession→GO | UniProt `idmapping_selected.tab.gz` (GO col, keyed on **RefSeq** col) | mapping | huge; indexed into partitioned Parquet/DuckDB keyed by accession; streamed join |
| `interpro2go` | EBI | interpro merge | small flat IPR→GO map |
| EC | GO `ec2go` + UniProt idmapping EC col | EC stage | |
| KEGG KO + pathway | UniProt idmapping KEGG col + KO→pathway map | KEGG stage | avoids KEGG REST license |

**The one heavy build** is the accession→GO/EC/KO index: `fetch` downloads
`idmapping_selected.tab.gz`, extracts the accession + RefSeq + GO + EC + KEGG
columns, and writes a sorted/partitioned Parquet (or DuckDB table). At runtime the
mapping stage does an indexed, streamed join of DIAMOND `sseqid` (RefSeq protein)
against the **RefSeq column**. WP_ MULTISPECIES proteins (cyanobacteria) have
moderate UniProt coverage, so a coverage report is emitted. If coverage proves
thin, the NCBI-native `gene2accession → gene2go` route is a drop-in supplement
(noted, not built initially).

## 6. The Annotation Rule (fidelity core)

Faithful to Götz et al. 2008; all constants configurable with Blast2GO defaults.

**Per query sequence:**
1. **Hit filtering** — drop hits with `evalue > evalue_hit_filter` (default
   `1e-6`); optional `hsp_coverage` minimum; cap at `num_hits` (default 20).
2. **Per-hit similarity** — `similarity = ppos` of the hit's best HSP, from the
   DIAMOND `ppos` column.
3. **Candidate GO pool** — each surviving hit accession → its GO terms (mapping
   stage), each tagged with the GO's source evidence code.
4. **Direct Term score** per candidate GO:
   `DT(go) = max over contributing hits of ( similarity_hit × ECW(evidence) )`
   where `ECW` is the configurable Evidence Code Weight table.
5. **DAG propagation / abstraction** — propagate DT scores up the GO DAG
   (`is_a`/`part_of`), then:
   `AS(go) = 100 × propagatedDT(go) + GOweight × (#child terms in the candidate pool mapping to this node)`
   where `propagatedDT(go) = max(DT(go), max DT over candidate descendants of go)` and
   `GOweight` default 5. The ×100 puts AS on the same 0–100 scale as the cutoff
   (default 55); a term is rewarded when corroborated by multiple specific children.
6. **Selection** — per DAG branch, assign the **most specific** node with
   `AS ≥ annotation_cutoff` (default 55). Assigned GOs carry their AS into output.

```yaml
annotation:
  evalue_hit_filter: 1.0e-6
  annotation_cutoff: 55
  go_weight: 5
  hsp_coverage: 0.0
  num_hits: 20
  ecw: {EXP: 1.0, IDA: 1.0, IPI: 1.0, IMP: 1.0, IGI: 1.0, IEP: 1.0,
        ISS: 0.8, ISA: 0.8, ISM: 0.8, ISO: 0.8, IBA: 0.8,
        TAS: 1.0, NAS: 0.7, IC: 0.8, IEA: 0.7, ND: 0.0}
```

The abstraction/selection step (5–6) is the subtle part; implemented carefully
against the published description and validated against the Chroococcidiopsis
fixture (assigned-GO counts as a sanity benchmark).

## 7. Outputs

- `clusterProfiler/` — `go_term2gene.tsv`, `go_term2name.tsv`,
  `kegg_term2gene.tsv`, `kegg_term2name.tsv` (loadable by the R DEA enrichment).
- `annotation.annot` — classic Blast2GO tab format (SeqName, GO/EC, name).
- `annotation.parquet` / `.tsv` — rich per-sequence master (assigned GOs + AS +
  evidence, InterPro, EC, KO, pathways, top-hit description).
- `summary/` — counts, GO-level distribution, GO-slim reduction (slim OBO), and
  the accession→GO coverage report (fraction of `sseqid` resolved via idmapping).

## 8. Error handling

- Validate at boundaries: Pydantic config; assert DIAMOND input has required
  columns incl. `ppos`; verify each reference file against cache `manifest.json`
  hash before a run; fail fast with clear messages.
- Stream the large idmapping join rather than loading wholesale.
- Per-stage Parquet checkpoints → a failed stage resumes without re-running
  upstream.
- Unresolved accessions are logged and counted, never silently dropped.

## 9. Testing & acceptance

**Unit (≥80% coverage):** ECW scoring; DAG propagation/abstraction on a tiny
hand-built GO DAG with known expected assignments; DIAMOND and idmapping parsers;
each writer.

**Integration:** full pipeline on a small fixture (a few hundred Chroococcidiopsis
proteins) with a trimmed reference slice.

**End-to-end acceptance:** full run on `GCF_023558375.1` (all 5,627 proteins in
`references/GCF_023558375.1/protein.faa`).

**eggNOG-mapper benchmark (acceptance gate):** scripted `benchmark/` harness, run
via apptainer.
1. Run `eggnog-mapper` on `protein.faa` (apptainer container reused from store or
   pulled; eggNOG DB fetched on an internet-connected node) → `.emapper.annotations`
   (GO, EC, KEGG_ko, KEGG_Pathway).
2. Run `b2gx run` on the same proteins (DIAMOND vs nr → annotation).
3. Compare and report:
   - **Coverage**: # proteins with ≥1 GO / EC / KO per tool, and overlap.
   - **GO concordance**: per-protein **ancestor-aware** Jaccard / semantic
     similarity (propagate both tools' GO sets to ancestors before comparing —
     fair, because the Annotation Rule assigns abstracted terms).
   - **EC / KO agreement**: exact-match rates.
   - Output: `benchmark_report` (TSV summary + plots) plus headline concordance numbers.

eggNOG (orthology / eggNOG-DB) and `b2gx` (homology-transfer vs nr) use different
evidence, so the benchmark measures **concordance, not identity** — success is
landing in the same biological neighborhood with comparable coverage.
